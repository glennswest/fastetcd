## 3. Prior art for open issues

- **openraft 0.10.0 is out (2026-11-10)**, [release notes](https://github.com/databendlabs/openraft/releases/tag/v0.10.0). It is stable now, which was the condition in #97's "leave it until 0.10 is stable" option. It brings leadership transfer (what our #57 patch backports), pipelined replication, Pre-Vote, and "faster linearizable reads", and states that stored data keeps its 0.9 form. Upgrade needs code changes (Rust 2024, Rust >= 1.88). It may let us drop all three vendored patches (#97 leader replication, #167 replication_timeout, #57 transfer_leader) and with them #159 and #175. 0.9.26 ([notes](https://github.com/databendlabs/openraft/releases/tag/v0.9.26)) is wasm-build only; nothing for us. Filed as an issue.
- **redb 2.6.4** (2026-10-02, [releases](https://github.com/cberner/redb/releases)): "Fix unbounded memory growth in the page cache under write workloads, when the cache never reached its configured size limit." We have 2.6.3 (`Cargo.toml` says `2.2`, so `cargo update -p redb` takes it). This fits #155 (idle RSS tracks the data file) and #84's rising RSS floor. Also, redb has had `Database::cache_stats()` since 2.4.0, so the "redb does not report its cache size" gap noted on #155 can be closed with a gauge. redb 3.x/4.x need file-format changes (3.0 dropped format v2; `Database::upgrade()` exists in 2.6): a separate, larger decision, not proposed.
- #180/#135 (spinning-disk write stalls): no new material found.
